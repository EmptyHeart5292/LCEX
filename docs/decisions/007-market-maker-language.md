# ADR-007:做市服务使用 Go

- 状态:已确认(2026-08-30)

## 背景

做市服务语言候选:Go(与业务服务一致)/ Rust(与撮合引擎一致)/ Python(策略生态,如 Hummingbot)。

## 分析

做市的关键路径是**网络 I/O**:消费五个外部交易所的 WS 行情、向本所 order 服务下单、通过外部所私有 API 对冲。需要的是稳定的高并发连接管理与可预期的重挂节奏(10–100ms 级),而不是微秒级计算。真正延迟敏感的组件是撮合引擎,已由 Rust 承担(ADR-001)。

## 决策

使用 Go,与全部业务服务统一。约束:

1. 每个交易对一个独立的单 goroutine 策略循环,状态不跨 goroutine 共享(与撮合引擎"单 symbol 单线程"同构),行为可预测、无竞态;
2. 与 price-index 共享同一个交易所连接器库(`packages/exchange-connector`):五所 WS/REST 接入、HMAC 签名、心跳重连,一份代码两个服务复用;
3. 做市订单必须走 order 服务正常链路,不提供旁路。

## 后果

- 与 order 服务 gRPC 对接、共享 Kafka 客户端/配置/可观测性设施,无跨语言成本;
- 招聘与维护只需一门业务语言;
- 未来若加入吃单型、跨所套利等延迟敏感策略,再将热路径下沉为 Rust;当前锚定挂单策略不需要,不为它预付 Rust 的开发成本。
