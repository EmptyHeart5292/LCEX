# 总体架构

## 1. 服务拓扑:交易主链路

```
                      ┌────────────────────────────────────────────┐
                      │       用户(apps/web,未来 apps/mobile)        │
                      └──────┬───────────────────────┬─────────────┘
                             │ REST                  │ WebSocket
                      ┌──────▼───────────────────────▼───────────┐
                      │  api-gateway:鉴权 · 限频 · 幂等 · WS 推送    │
                      └──────┬───────────────────────▲───────────┘
                             │ 下单/撤单               │ 行情/订单/余额推送
                      ┌──────▼──────┐                 │
                      │    order     │ 校验 → 冻结资金   │
                      └──────┬──────┘                 │
                             │ 订单事件                 │
                             ▼                        │
              ╔═══════════════════════════════════════╪════════════╗
              ║             Kafka 事件溯源总线           │(消费)      ║
              ╚═════════▲═══════════════════╤═════════╧════════════╝
                        │                   │
        订单事件          │                   │ 成交/订单状态事件
              ┌─────────┴────────┐          ├────────────► api-gateway(WS 私有推送)
              │     matching      │          ├────────────► clearing(复式记账)
              │ Rust·单symbol单线程│          └────────────► market(深度/ticker/K线)
              │ 价格时间优先·可重放 │
              └──────────────────┘
```

risk 与 wallet 同样以事件订阅方式接入总线。clearing 更新的余额落 PostgreSQL。

## 2. 做市与指数链路(对齐外部交易所价格)

```
 Binance / OKX / Bybit / MEXC / Bitget 公共行情
                    │
             ┌──────▼───────┐   指数价    ┌─────────────────┐
             │  price-index  │──────────▶│  market-maker    │
             │ 加权 · 剔异常源 │            │ 双边报价 · 库存偏移 │
             └──────┬───────┘            └───────┬─────────┘
                    │ 指数价                      │ 做市订单
                    ▼                            ▼
        market(薄盘时回退展示指数)       order → matching → clearing
                                                  │(与普通用户完全同链路,
                                                  │  不绕过风控与账本)
                                                  ▼
                                     外部交易所私有 API(库存对冲,保持中性)
```

要点:

- **price-index** 加权计算指数价,自动剔除偏离超阈值、心跳超时的异常源;输出 Kafka + Redis,供做市、行情回退展示、风控参考价(二期合约的标记价格也用它)。
- **market-maker** 以指数价为锚双边挂单;价差、单量、刷新阈值、库存上限按交易对配置;价格移动超阈值或部分成交后 cancel/replace;库存偏离目标时调整报价偏移并通过外部交易所私有 API 对冲。
- 风控红线:与指数价最大偏移限制、最大挂单名义额、对冲通道故障自动停止报价、全局 kill switch。
- 本所成交价与指数价偏离持续过大时,risk 告警并可熔断。

## 3. 充值 / 提现链路

- **充值**:用户获取独立充值地址(wallet 经托管商 HD 派生)→ 扫链/回调监听 → 确认数达标 → 幂等入账(UTXO 按 txid+vout,EVM 按 txid+合约转账索引,Solana 按 txid+账户索引)。
- **提现**:申请 → risk 规则(限额/名单/制裁筛查接口)→ 大额人工 4-eyes 审核(Admin)→ 托管商签名广播 → 链上确认闭环。
- **对账**:每日三方对账——链上余额 vs 内部账本 vs 充提记录,差异触发最高级告警。
- 热钱包余额超阈值自动归集(托管商能力或自建 sweep 任务)。

## 4. 存储分工

| 存储 | 用途 |
|---|---|
| PostgreSQL | 账本(journal/ledger_entry)、账户、订单、提现记录 |
| Kafka | 全部事件流:订单、成交、余额变更、指数价、充提状态(事件溯源,可重放) |
| Redis | 热点行情、限频计数、会话、名单缓存 |
| ClickHouse | K线与历史成交 |

## 5. 一致性原则(全系统不变式)

1. 余额只由账本流水推导,任何资金变动必是借贷平衡的分录;每日重放流水校验,不平即告警并冻结相关功能。
2. Kafka at-least-once 投递 + 全部消费端幂等(按业务 ID 去重)= 业务上恰好一次。
3. 撮合输出全局单调递增 sequence,行情与推送下游按 sequence 校验连续性,断线后按 sequence 补齐。
